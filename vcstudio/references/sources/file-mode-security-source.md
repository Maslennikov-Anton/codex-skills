Реализация

- в Project Editor добавить вкладку Security / Безопасность

- на этой вкладке разместить чекбокс Enable / Включить

- если чекбокс включён, безопасность работает как обычно

- если чекбокс выключён:

- не показывать login dialog при открытии файлового проекта

- автоматически входить в студию как admin

- не запускать screen lock

Дополнительно:

- настройка должна сохраняться в vcsys в секции ExtendedSettings/SecuritySettings

- если секции нет, считать безопасность включённой

- изменение настройки должно быть доступно только admin

- настройка должна работать только для file mode

- для database mode ничего не менять

- нужно добавить подпись настройки, чтобы простая ручная правка vcsys без корректной подписи не отключала безопасность

Тестирование

Нужно проверить новую проектную настройку безопасности для file mode.

1. В новом файловом проекте:

- на вкладке Security / Безопасность чекбокс Enable включён

- при открытии проекта login dialog показывается

- screen lock работает

2. При снятии Enable и сохранении проекта:

- после повторного открытия проекта login dialog не показывается

- студия входит как admin

- screen lock не работает

3. Если снова включить Enable:

- login dialog снова должен показываться

- screen lock снова должен работать

4. Проверить vcsys:

- настройка сохраняется в ExtendedSettings/SecuritySettings

5. Проверить защиту:

- вручную испортить fileModeAuthSignature

- открыть проект

- безопасность не должна отключаться, login должен снова запрашиваться

6. Проверить database mode:

- новая логика не должна менять существующее поведение входа и блокировки.

PR adds a full local security mechanism for file-mode projects in VCStudio.

Main changes:

added local users/roles storage inside .vcsys for file mode;

added encrypted users container with project binding and recovery session flow;

added built-in default users for new file projects:

admin/admin

engineer disabled by default

system user recovery;

added login for file-mode projects with recovery mode support;

added password change flow for current user;

added project-level security management UI in project properties:

enable/disable security

users table

create/edit/delete users

activate/deactivate users

password reset/change;

added file-mode security audit into project audit/;

added recovery CLI support for generating recovery password by Session ID;

updated new file project flow:

project opens immediately

automatic login under default admin/admin;

removed obsolete File menu action for password change;

added lock screen updates for file mode;

changed File -> Recent projects behavior:

menu is disabled when the recent-projects list is empty.
