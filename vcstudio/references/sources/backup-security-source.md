```text
 1. Восстановление проекта из резервной копии
 Назначение и хранение
 VCStudio может автоматически создавать снимки состояния проекта. Снимок включает файл .vcsys и файлы
 библиотеки типов проекта. Снимки хранятся в каталоге backup внутри каталога проекта. Одинаковые файлы
 между снимками не дублируются физически, поэтому размер хранилища обычно меньше суммы размеров всех
 версий.

 Откройте редактор проекта и перейдите на вкладку «Восстановление». В этой вкладке отображаются настройки
 снимков, занимаемый ими объём и их количество.

 Настройка автоматических снимков
 Для обычного проекта рекомендуется оставить включёнными первые четыре опции:
    •    «Включить снимки резервной копии» — общее включение механизма. Если снять флажок, новые
         автоматические и ручные снимки не создаются.
    •    «Создавать снимок при сохранении проекта» — сохраняет версию после сохранения проекта.
    •    «Создавать снимок после успешной загрузки» — сохраняет версию только после успешной загрузки (deploy)
         проекта в контроллер.
    •    «Разрешить ручное создание снимков» — позволяет использовать кнопку «Сделать снимок».
    •    «Разрешить ручные снимки без изменений» — создаёт ручной снимок даже если файл проекта и библиотека
         не изменились с предыдущего снимка.
    •    «Сохранять ручные снимки при автоочистке» — защищает ручные снимки от удаления правилами хранения.
 Поля «Максимум автоматических снимков» и «Максимальный размер хранилища, МБ» ограничивают историю. При
 достижении ограничения Studio удаляет наиболее старые автоматически созданные снимки; ручные снимки
 сохраняются, если включена соответствующая опция. Значение 0 означает отсутствие ограничения для данного
 поля. Вводятся только неотрицательные целые числа.

 Снимок не создаётся повторно, когда с прошлого снимка нет изменений — кроме случая, когда разрешены ручные
 снимки без изменений.

 Создание снимка вручную
    1    Откройте вкладку «Восстановление».
    2    Нажмите «Сделать снимок».
    3    При необходимости введите комментарий: например, до изменения сети Modbus.
    4    Подтвердите создание и убедитесь, что счётчик снимков увеличился.
 Комментарии особенно полезны перед экспериментами, массовой заменой типов или загрузкой в контроллер.

 Восстановление версии
 Перед восстановлением сохраните текущую полезную работу отдельно: восстановление «на месте» заменяет
 текущий .vcsys и библиотеку теми, что есть в выбранном снимке.
    1    Откройте «Восстановление» «Восстановить проект».
    2    Выберите каталог backup. Для открытого проекта он подставляется автоматически.
    3    Выберите нужный снимок. В окне доступны его дата, причина создания, версия проекта, версия Studio и
         комментарий.
    4    Выберите вариант:
            •      восстановить локально — заменить файлы текущего проекта;
            •      восстановить как новый проект — безопасный рекомендуемый вариант: задайте новое имя и каталог,
                   чтобы получить отдельную копию проекта.
    5    Нажмите «Восстановить». После успешной операции Studio открывает восстановленный проект.
```

```text
 2. Вкладка «Безопасность»
 Вкладка «Безопасность» видна в редакторе проекта только после входа с ролью admin. Она управляет локальными
 пользователями именно этого .vcsys-проекта.

 Как работает защита
 Список пользователей находится не в отдельном файле, а внутри .vcsys. Контейнер пользователей зашифрован и
 связан с конкретным проектом; пароли внутри него хранятся как стойкие хеши. Поэтому нельзя корректно
 перенести блок безопасности в другой проект или вручную поменять пароль в XML.

 Доступны две роли:
    •    admin — полный доступ, управление пользователями и включение/отключение безопасности;
    •    engineer — работа с проектом без управления пользователями и глобальными security-настройками.
 Для нового файлового проекта создаются:
    •    активный пользователь admin с начальным паролем admin;
    •    неактивный пользователь engineer;
    •    системный пользователь recovery для аварийного доступа.
 После первого входа рекомендуется сразу изменить пароль admin и создать персональные учётные записи.
 Системного пользователя recovery нельзя удалить, заблокировать, переименовать или изменить ему пароль.

 Управление пользователями
    1    Войдите как admin и откройте проект в редакторе.
    2    Перейдите на вкладку «Безопасность».
    3    Создавайте пользователя кнопкой добавления, задавая логин, имя, пароль и роль.
    4    Выберите пользователя в таблице, чтобы изменить его данные, сбросить пароль,
         заблокировать/разблокировать или удалить его.
 Администратор не может удалить текущую учётную запись, последний активный обычный admin и системного
 пользователя. При сбросе пароля другому пользователю ему будет предложено задать новый пароль при
 следующем входе.

 Включение и отключение входа
 Флажок «Включить безопасность» означает, что при открытии проекта показывается окно входа и работает
 блокировка экрана. Этот режим рекомендуется для рабочих проектов.

 Снять флажок может только admin. В таком случае следующий раз проект открывается автоматически от имени
 admin, без окна входа и без блокировки экрана. Перед включением защиты обратно Studio отдельно просит
 убедиться, что известен пароль активного администратора.

 Настройка также защищена от простого ручного редактирования и копирования между проектами. Если её подпись
 отсутствует или не совпадает, Studio безопасно включает авторизацию.
```

## Страница 4

```text
VCStudio / Резервные копии · Безопасность · Целостность




     Важно: если .vcsys необходимо отредактировать вручную, сначала отключите «Включить безопасность» в Studio.
     Затем отредактируйте файл и после завершения изменений снова включите безопасность. Не редактируйте
     защищённый .vcsys вручную при включённой локальной безопасности.


 Контейнер пользователей криптографически привязан к содержимому конкретного проекта. Поэтому изменение
 модели, текста, XML-структуры или security-атрибутов в текстовом редакторе при включённой локальной
 безопасности не сопровождается штатным перерасчётом и перешифрованием контейнера. В том числе не следует
 менять, удалять, усекать или переносить в другой .vcsys атрибуты fileModeUsersVersion,
 fileModeUsersBlob, fileModeUsersBindingTag и настройки авторизации.

 При открытии Studio не доверяет повреждённому или несогласованному контейнеру и показывает сообщение
 «Локальные данные безопасности повреждены». Это ожидаемое защитное поведение: Studio не пытается угадать
 или восстановить прежние пароли.

 Если .vcsys уже был изменён вручную при включённой безопасности и нужно сохранить ручные изменения в
 логике, используйте описанное ниже аварийное восстановление: оно сформирует новый корректный контейнер
 безопасности для уже изменённого файла. Если важнее сохранить существующие учётные записи и их пароли,
 восстановите весь .vcsys из снимка, сделанного до ручного изменения. Простое копирование security-атрибутов
 из старой версии не исправит изменённый проект.

 Аварийное восстановление локальной безопасности
 Этот сценарий сбрасывает только локальный список пользователей к штатному состоянию. Он не восстанавливает
 прежние пароли, созданные учётные записи и их настройки.
    1    На окне входа нажмите «Восстановить».
    2    Откроется режим восстановления: логин фиксирован как RECOVERY, а на экране появится Session ID.
    3    Передайте Session ID в авторизованную службу поддержки/производителю. Не публикуйте его в общем
         чате, заявке с широким доступом или журнале.
    4    Поддержка запускает служебную recovery-утилиту и выдаёт временный пароль для этого Session ID.
    5    Введите полученный пароль и нажмите «Войти».
    6    Studio восстановит штатный локальный контейнер пользователей и подтвердит это сообщением. После этого
         закройте и снова откройте проект, войдя как admin с паролем admin.
    7    Немедленно смените пароль admin, создайте нужные учётные записи и проверьте состояние флажка
         «Включить безопасность».
 У recovery-пароля нет значения по умолчанию. Он вычисляется из Session ID, действует только для текущего
 окна входа и становится недействительным после его закрытия. Не путайте его с начальным паролем обычной
 учётной записи: для нового или сброшенного локального контейнера начальные данные — admin / admin.

 Если пароль recovery не принят, не закрывайте окно входа: закрытие создаёт новую login-session и прежний
 пароль перестаёт работать. Сверьте Session ID, запросите новый пароль для отображаемого значения и
 повторите вход. Если восстановление завершилось с ошибкой, сохраните исходный .vcsys и каталог backup без
 дальнейшего редактирования и передайте их в регламентную поддержку.
```
