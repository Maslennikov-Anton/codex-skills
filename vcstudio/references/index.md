## Источники и справочники — sources/

Это встроенные материалы для полноты и точных формулировок. Прежний путь
внешнего файла — происхождение, а не обязательная зависимость.

| Материал | Как пользоваться |
| --- | --- |
| [VC024SA.B: основные факты](sources/vc024sa-key-facts.md) | Плотный справочник по документу: от установки и модели до ST, мониторинга, Modbus и OPC UA. Более новые правила снимков/доступа смотри в guides. |
| [Карта разделов VC024SA.B](sources/vc024sa-section-map.md) | Фактическая нумерация тела и метки `Lxxxx`; особенно нужна для `6.7+`. |
| [Полный текст VC024SA.B](sources/vc024sa-complete.md) | Все извлечённые разделы, таблицы, подписи рисунков; сначала найди диапазон по карте. Внешний PDF/DOCX не нужен. |
| [Инструкция: снимки, безопасность и целостность](sources/backup-security-source.md) | Полный текст четырёх страниц, версия документа 2. Страницы 2–3 — снимки, 3 — пользователи, 4 — правка/recovery. Номер документа не является версией Studio. |
| [VCONT-2027/VCONT-2127](sources/file-mode-security-source.md) | Полные экспорты с тест-планом, комментарием 17.08.2026 и связями VCONT-2221/VCONT-2222. Сохраняй уточнения и отличай историю задач от текущего результата продукта. |
| [Каталог 473 интерфейсов ФБ](sources/fb-typelibrary-catalog.md) | Snapshot от 27.05.2026. Ищи точный блок через `rg`, затем проверяй доступность в используемой поставке. |
| [Происхождение и проверки исходников](sources/source-provenance.json) | Commit/capture, SHA256, статус semantic review и проверенный framing поставки. Даты и hashes не обновляют сами себя при перестройке skill. |

Например, из каталога skill:

```bash
rg -n 'EIPDIAG' references/sources/fb-typelibrary-catalog.md
rg -n 'L2976|8\. Коммуникационные' references/sources/vc024sa-complete.md
```

## Датированные проверки — evidence/

[Аудит VCONT-2027/VCONT-2127 от 11.11.2026](evidence/file-mode-security-test-impact.md)
содержит сопоставление требований с тестами/bridge, результаты выборочных E2E,
пробелы покрытия и последующую актуализацию. Два снимка UI лежат рядом в
`evidence/images/` и доступны из аудита. Это историческое свидетельство,
а не текущая очередь исправлений или полная квалификация безопасности.

Контекст шести перенесённых проектов и наблюдавшиеся преобразования сохранены
в руководстве [project-salvage.md](guides/project-salvage.md), разделы
«Наблюдаемые преобразования Studio» и «Результаты шести входов»; это границы
применимости процедуры, а не универсальные числа для любого проекта.

## Как добавлять знания и не дробить их

1. Определи владельца темы по первой таблице. Дополняй существующее руководство;
   новый файл нужен для самостоятельной процедуры, а не очередного эпизода.
2. В руководстве оставляй условия, точные действия/поля, ожидаемый результат,
   ограничения и переход к следующему действию. Повторяющийся контракт храни
   у владельца темы, из соседних руководств давай ссылку.
3. Для нового PDF/DOC переноси внутрь sources полный нужный текст, таблицы,
   комментарии и значимые изображения. Рабочий порядок изложи в guides;
   путь к оригиналу или внешнему отчёту не заменяет это содержание.
4. Помечай основание: требование документа; согласованное уточнение;
   наблюдение конкретной версии с датой/артефактом; открытый вопрос.
   При конфликте сохрани обе формулировки и объясни применимость.
   Изменение реализации само по себе не отменяет требование.
5. Результаты конкретных прогонов держи в evidence с датой, составом проверки
   и ограничениями. Не превращай старое падение в постоянное правило продукта;
   не объявляй весь контракт проверенным по одному smoke или bytecode.
6. Обнови эту карту и затронутые перекрёстные ссылки. Перед завершением проверь
   целостность переносимых разделов, локальные ссылки/доступность материалов,
   отсутствие внешней обязательной зависимости и валидность skill.
