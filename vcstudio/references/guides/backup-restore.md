## Выбор операции

| Задача | Операция | Последствие |
| --- | --- | --- |
| Вернуть прежнюю модель и библиотеку | Восстановить выбранный снимок | Возвращается версия из снимка; последующие изменения в неё не входят |
| Получить отдельную восстановленную копию | Восстановить `как новый проект`, задать новое имя и каталог | Позволяет сохранить текущую рабочую копию отдельно |
| После ручной правки сохранить прежние учётные записи и пароли | Восстановить весь `.vcsys` из снимка до правки | Ручные изменения после снимка теряются в восстановленном файле |
| Сохранить ручные изменения логики при несогласованном контейнере | [Recovery локальной безопасности](security-recovery.md) | Создаётся новый контейнер; прежние пользователи, пароли и их настройки не возвращаются |
| Спасти содержимое старого корректного XML без recovery-пароля | [Перенести модель в новый проект](project-salvage.md) с предварительно отключённой через UI безопасностью | Отдельная новая копия со своими пользователями; требуется проверка задач, настроек, типов и преобразований формата |
| Проект утрачен, но `backup` сохранился | `Файл` → `Восстановить проект` → `как новый проект` | Достаточно доступного каталога снимков по описанному сценарию |

`Восстановить проект` и `Восстановить` в окне входа — разные операции. Не сбрасывай пользователей вместо отката модели. Если задача требует сохранить одновременно новые правки и прежние учётные записи, инструкция не даёт такого способа через перенос security-атрибутов.

## Снимки и хранилище — страницы 2–3

Снимок содержит `.vcsys` и файлы библиотеки типов проекта. Хранилище — `backup` внутри каталога проекта. Одинаковые файлы между снимками физически не дублируются; конкретный алгоритм хранения не указан. Из расположения следует: потеря всего каталога может уничтожить и проект, и его снимки; внешнее резервирование здесь не описано.

На вкладке `Восстановление` видны настройки, объём и число снимков:

| Настройка | Поведение |
| --- | --- |
| `Включить снимки резервной копии` | Общий выключатель; без него не создаются ни автоматические, ни ручные снимки |
| `Создавать снимок при сохранении проекта` | Снимок после сохранения проекта |
| `Создавать снимок после успешной загрузки` | После успешного deploy проекта в контроллер; не означает открытие файла в Studio |
| `Разрешить ручное создание снимков` | Разрешает кнопку `Сделать снимок` |
| `Разрешить ручные снимки без изменений` | Позволяет повторный ручной снимок при неизменных проекте и библиотеке |
| `Сохранять ручные снимки при автоочистке` | Защищает ручные снимки от правил хранения |

Первые четыре флажка рекомендованы инструкцией для обычного проекта; это не утверждение о заводских значениях. Без изменений с предыдущего снимка повтор не создаётся, кроме разрешённого ручного снимка без изменений. Не обещай увеличение счётчика после каждого сохранения или нажатия кнопки.

`Максимум автоматических снимков` и `Максимальный размер хранилища, МБ` принимают неотрицательные целые числа; `0` отключает соответствующее ограничение. При достижении лимита удаляются наиболее старые автоматические снимки; ручные сохраняются при включённой защите. Не определено, что делать, если одни защищённые ручные снимки превышают размер, и как удаляются ручные при выключенной защите.

Ручной снимок: `Восстановление` → `Сделать снимок` → необязательный комментарий → подтверждение. Для контроля результата учитывай флажки и наличие изменений.

Восстановление версии:

1. Сохрани полезную текущую работу отдельно: восстановление на месте заменяет текущие `.vcsys` и библиотеку.
2. Открой вкладку `Восстановление` → `Восстановить проект`; выбери `backup` (для открытого проекта подставляется автоматически).
3. Выбери снимок по дате, причине создания, версии проекта, версии Studio и комментарию.
4. Выбери восстановление локально либо `как новый проект` с новым именем и каталогом. Второй вариант рекомендован инструкцией для отдельной копии.
5. Нажми `Восстановить`; после успешной операции Studio открывает восстановленный проект.

После восстановления проверь модель и библиотеку выбранного снимка. Требования
к пользователям/паролям, сохранению текущего audit и событию `PROJECT_RESTORED` —
в [file-mode-security.md](file-mode-security.md), раздел «Хранение, привязка и штатные операции».
Само открытие восстановленного файла не подтверждает все эти результаты.

`Очистить хранилище` необратимо удаляет всю историю снимков, оставляя текущий проект. Защита ручных снимков заявлена для автоочистки; она не является обещанием их сохранения при очистке всего хранилища.
