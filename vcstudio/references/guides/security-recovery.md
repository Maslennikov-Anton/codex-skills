# Целостность .vcsys, ручная правка и recovery доступа

Сброс пользователей отличается от восстановления версии проекта и переноса
модели. Выбор операции и последствия — в [backup-restore.md](backup-restore.md),
роли и обычный вход — в [file-mode-security.md](file-mode-security.md).
Основания: встроенные [четыре страницы инструкции](../sources/backup-security-source.md)
и [VCONT-2027/VCONT-2127 с комментариями](../sources/file-mode-security-source.md).
Наличие инструкции не подтверждает выполнение recovery на произвольной сборке.

## Ручная правка .vcsys — страница 4

При включённой локальной безопасности не редактируй `.vcsys` внешним редактором/скриптом. Контейнер связан с содержимым проекта: изменение модели, текста, XML-структуры или security-атрибутов вне Studio не выполняет штатный пересчёт и перешифрование.

Не удаляй, не меняй, не усекай и не переноси в другой `.vcsys` атрибуты `fileModeUsersVersion`, `fileModeUsersBlob`, `fileModeUsersBindingTag` и настройки авторизации. Копирование security-атрибутов из старой версии не чинит уже изменённый проект.

Документированный порядок: сначала отключить `Включить безопасность` в Studio → внести ручные изменения → снова включить безопасность в Studio. Уточнения рабочего процесса ниже — наши меры против потери правок, а не дополнительные обещания PDF:

- До правок сохрани исходный проект и `backup` отдельно; изменяй рабочую копию.
- При успешном штатном отключении сохрани проект и закрой его перед внешней правкой, чтобы открытая модель не перезаписала файл.
- После правок открой проект через Studio, включи безопасность штатно и сохрани; проверь повторное открытие, ожидаемую логику и нужные учётные записи. PDF не описывает точный момент пересчёта привязки — не обещай сохранность пользователей только по нажатию флажка.

Если уже видно `Локальные данные безопасности повреждены`, сначала сохрани исходный файл и выбери требуемый результат по таблице в [backup-restore.md](backup-restore.md). В описанном сценарии ручной правки защищённого файла это ожидаемая защита. Однако сообщение само по себе не доказывает ручную порчу: совместимость, миграция и возможные сбои требуют отдельной проверки. Не объявляй повреждение после штатной работы Studio нормой только на основании этой инструкции.

## Recovery локальной безопасности — страница 4

Recovery сбрасывает локальный список пользователей к штатному состоянию и формирует контейнер для уже изменённого файла. Это позволяет сохранить ручные изменения логики, но не возвращает прежние пароли, созданные учётные записи и их настройки.

1. В окне входа нажми `Восстановить`.
2. В режиме восстановления логин фиксирован как `RECOVERY`; считай текущий `Session ID`.
3. Передай Session ID авторизованной поддержке/производителю по закрытому каналу. Не публикуй его в общем чате, заявке с широким доступом или журнале; в общих вложениях скрывай его.
4. Авторизованная поддержка выдаёт временный пароль через служебную recovery-утилиту. Сам PDF её не содержит; предоставленный VCONT-2127 описывает штатный пакет с Java и запуск `vcstudio-filemode-recovery --session-id '<SESSION_ID>'`, см. [раздел о штатной утилите](#повреждение-контейнера-и-штатная-утилита). Авторизованный оператор с предоставленным пакетом может использовать этот штатный путь. Без пакета или выданного поддержкой пароля не обещай локальный recovery и не подменяй утилиту собственной генерацией.
5. Не закрывая это окно, введи выданный пароль и нажми `Войти`.
6. После сообщения об успешном восстановлении закрой и снова открой проект; войди `admin` / `admin`.
7. Немедленно смени пароль admin, создай нужные персональные учётные записи и проверь состояние `Включить безопасность`.

У recovery нет пароля по умолчанию: `admin/admin` относится к обычному admin нового/сброшенного контейнера. Временный recovery-пароль действует только для текущего окна входа; после его закрытия недействителен. Дополнительный TTL или лимит попыток в PDF не задан.

При непринятом пароле не закрывай окно: сверь отображаемый Session ID и запроси актуальный пароль для него. Если само восстановление завершилось ошибкой, сохрани исходные `.vcsys` и `backup` без дальнейшего редактирования для регламентной поддержки. Не продолжай перебором паролей или правкой контейнера.

## Повреждение контейнера и штатная утилита

Проверки порчи выполняются на отдельных копиях при закрытой Studio: изменить blob, binding, удалить security-атрибут или перенести users-контейнер из проекта A в B. При включённой защите ожидаются диагностический отказ, отсутствие автоматического admin-входа и доступность recovery. `admin/admin` не является обходом повреждённого контейнера. Если повреждение произошло после штатной операции Studio, это не становится нормой только потому, что защита умеет распознавать порчу.

Recovery использует системного `RECOVERY` и временный пароль **для текущего Session ID текущего окна входа**. Закрытие окна/Studio инвалидирует старую сессию; в новой нужен новый пароль. Для повреждённого контейнера успешное recovery возвращает admin/admin, неактивного engineer и системного recovery, сохраняя модель проекта. Старые персональные пользователи этим способом не восстанавливаются.

В пункте 10 задачи описана штатная утилита `vcstudio-filemode-recovery-linux-x86_64.tar.gz`, путь в исходном репозитории `tools/filemode-recovery/dist/`. Архив содержит Java runtime. У авторизованного оператора после распаковки запуск выглядит так:

```text
<каталог распаковки>/vcstudio-filemode-recovery/bin/vcstudio-filemode-recovery --session-id '<SESSION_ID>'
```

Допустима форма `--session-id='<SESSION_ID>'`; ожидается один временный пароль из 20 символов. Используй предоставленный штатный артефакт, не извлекай секреты из JAR и не заменяй утилиту собственной генерацией. В проверенном архиве самой Studio отдельного recovery-дистрибутива не найдено; наличие `FileModeRecoveryCli.class` ещё не доказывает наличие готового пакета с Java. Если утилита оператору недоступна, пароль получает авторизованная поддержка.

Пункт 10 исходного тест-плана требует видеть Session ID сразу; текущий `LoginDialog.updateRecoveryModeUi()` показывает его при включённом recovery-режиме, что соответствует пошаговому пути PDF через `Восстановить`. Различие с требованием «сразу» фиксируй отдельно. Оно не отменяет ни обычный login, ни контроль точного проекта, ни требования проверки recovery-сессии.

## Применение в автоматизации

- Для подготовки обычных тестовых проектов используй штатное редактирование Studio. Внешние преобразования защищённых `.vcsys`, включая массовые замены XML, могут нарушить привязку; не считай их безусловно нейтральной подготовкой fixture.
- Recovery, отключение безопасности и замена файла снимком меняют тестируемое состояние. Не выполняй их скрытно, чтобы обойти падение позитивного теста. При диагностике сохраняй исходный fixture, версию/хеш Studio и точное сообщение; исходные failed/broken остаются исходными результатами.
- Различай наличие предупреждения/кнопки и успешный вход. Изменение состава формы не доказывает ни невозможность входа, ни успешность recovery. Не заменяй проверку открытия проекта принятием текста ошибки.

PDF не устанавливает миграцию старых контейнеров/снимков, поведение при частично повреждённом backup/недостатке места/прерывании восстановления и состояние флажка защиты после recovery. Требования сохранения пользователей при Rename/Save As и их восстановления из backup дополнены VCONT-2127 в [file-mode-security.md](file-mode-security.md); связанные VCONT-2221/VCONT-2222 нельзя считать автоматически исправленными. При зависимости задачи от деталей сверяй конкретный артефакт, не придумывай oracle.
