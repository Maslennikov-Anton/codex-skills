# VCStudio Project Workflow

For the backend/runtime mapping of this project model into VCont tasks, loops, FB paths, bootfile commands, and HSB boundaries, see `studio-vcont-contract.md`.

## Назначение

VCSystem состоит из среды исполнения VCont и среды разработки VCStudio. VCStudio конфигурирует системные настройки контроллера, коммуникации и логические схемы управления.

Проект VCStudio - совокупность устройств, ресурсов и логических схем с общим адресным пространством. На старте выбирается директория проекта; существующий проект открывается через файл `.vcsys`. В одном экземпляре VCStudio может быть открыт только один проект.

Авторизация по умолчанию в документе: login `admin`, password `admin`.

## Инсталляция и запуск

Требования из документа:

- VCStudio: от 8 GB RAM, HDD 500 GB, x86_64 Core i5+, Astra Linux 1.7+, Ubuntu 20.04+, Debian 12+, Windows 10+.
- VCont emulator: от 2 GB RAM, HDD 500 GB, x86_64 Core i5+, те же ОС.
- VCont operational mode: Linux-like система с настройками детерминированного real-time режима; настройка ОС под realtime выполняется сервисными инженерами.
- Linux install path examples: `/opt/vcstudio/`, `/opt/vcont/`.
- Windows: папки `vcstudio` и `vcont` должны лежать в корне диска, иначе возможны ошибки из-за длины путей.

Запуск: `vcstudio` на Linux, `vcstudio.exe` на Windows.

## Проект И Интерфейс

Создание нового проекта:

1. Запустить VCStudio.
2. Авторизоваться.
3. В окне `Открытие проекта` нажать `Новый проект`.
4. В окне `Новый проект VCStudio` выбрать шаблон.
5. Ввести имя проекта и расположение папки проекта.
6. Нажать `Создать`.

Открытие существующего проекта:

1. Запустить VCStudio и авторизоваться.
2. В окне `Открытие проекта` нажать `Обзор` либо выбрать проект из выпадающего списка.
3. В файловом менеджере выбрать проектный файл `.vcsys`.
4. Нажать `Открыть`.

Основные области интерфейса:

- `Структура системы`: создание и управление устройствами, ресурсами, приложениями, контурами.
- `Редактор`: редакторы объектов.
- `Навигация по контуру`: графическая навигация по рабочей области контура.
- `Свойства и сообщения`: свойства объектов и сообщения.
- `Библиотека`: библиотеки и ФБ, доступные для размещения в контуре.

Базовые настройки:

- Сброс расположения окон: `Окно` -> `Сброс перспективы`.
- Параметры: `Окно` -> `Параметры` -> `Общие`.
- Автосохранение: рекомендованный период не меньше 5 минут; `Ограничить запись истории` ограничивает рост backup/history.
- Внешний вид: themes require `Enable theming`.
- Горячие клавиши настраиваются на вкладке `Клавиши`; пример документа - `Ctrl+M` для `Мониторинг`.
- Цвета соединительных линий настраиваются по типу данных.
- Настройки monitoring включают цвета и период опроса; рекомендованное значение в документе - `300 мс`.
- Параметры загрузки включают timeout подключения к виртуальному контроллеру; рекомендованное значение - `10000мс`.
- Параметры контуров управления задают язык контура; для `Функциональная блок-схема` можно задать максимум блоков до предупреждения.
- Рабочая область контура настраивает сетку и соединительные линии.
- В `Расширенные настройки` документ требует включить все checkboxes, иначе подключение к VCont может не выполниться. Максимальное время блокировки при простое - 20 минут.

## Логи и архивы

Архивные файлы не очищаются автоматически:

- системные сообщения Studio: `/project_name/.metadata/.log`;
- backup/history проекта: `/workspace_name/.metadata/.plugins/org.eclipse.core.resources/.history/`.

Для автосохранения рекомендован период не меньше 5 минут. Чтобы ограничить рост истории, включают ограничение записи history.

Резервные копии также создаются при каждом сохранении проекта. Восстановление: кнопка `История изменений` на верхней панели -> выбрать дату backup -> `Заменить`. Двойной щелчок по backup-строке открывает сравнение текущего `.vcsys` с резервной копией в области `Сравнение текста`.

## Иерархия объектов

Главная цепочка:

```text
Project -> Device -> Resource -> Application -> Control Loop -> Function Blocks
```

- `Project`: единое адресное пространство; имена объектов должны быть уникальны.
- `Device`: сервер/промышленный компьютер, host для runtime resource.
- `Resource`: front-end representation of a target VCont endpoint/instance: IP/port, load database, tasks, online operations, communication settings. Do not confuse it with `Application`.
- `Application`: program namespace/group inside the resource; in runtime artifacts it becomes a name segment such as `APPLICATION1` in `APPLICATION1.LOOP1.FB`.
- `Control Loop` / `Контур управления`: связный алгоритм для одного объекта управления или группы сигналов.

Создание:

- device: контекстное меню проекта -> `Добавить устройство`; имя в документе ограничено 6 символами;
- resource: контекстное меню device -> `Добавить ресурс`; в свойствах указываются IP-адрес и порт VCont;
- application: контекстное меню resource -> `Добавить приложение`;
- control loop: контекстное меню application -> `Добавить контур управления`.

## Задачи

Контур управления должен быть назначен задаче. Типы задач:

- periodic/cyclic: ФБ выполняются один раз в заданный period;
- event: ФБ выполняются по event trigger.

Задачи редактируются в окне resource на вкладке `Задачи`. Для cyclic task задается period. В документе есть важное ограничение: нельзя назначать одинаковый period разным задачам. Если period удалить, cyclic task становится event task.

Назначение loop на task выполняется в свойствах loop через поле `Задача`.

## Функциональные блоки

ФБ добавляются из окна `Библиотека` в редактор контура. Библиотека содержит блоки IEC 61131-3 и VCont-specific блоки. Поиск доступен в библиотеке и через быстрый поиск `Ctrl+F`.

Быстрый поиск (`Ctrl+F`) ищет по началу имени контура, имени ФБ, типу ФБ, имени resource или device. Двойной щелчок по результату или кнопка `Открыть` переводит редактор к найденному месту и выделяет ФБ.

Внешний вид блока:

- входные порты слева, выходные справа;
- верхние визуально отделенные порты относятся к event tasks;
- внизу указан тип блока и номер выполнения;
- описание порта видно при hover;
- свойства порта показывают initial value, data type, comment, default value и incoming/outgoing connections.

Начальные значения входов по умолчанию не определены. После запуска, загрузки, init variables или reset resource неподключенные/неинициализированные входы обычно получают:

- `false` для BOOL;
- `0` для analog/numeric.

Initial value можно задать в свойствах ФБ, через графическое поле слева порта или через свойства порта.

Maintenance commands:

- `Заменить тип блока`: меняет тип существующего блока без разрыва связей и сохраняет совместимые начальные значения.
- `Обновить тип блока`: обновляет число/типы входов и выходов экземпляра после изменения его типа.

## ANY-типы

Порты `ANY`, `ANY_BIT`, `ANY_MAGNITUDE` и похожие могут принимать разные допустимые типы. По умолчанию arithmetic ФБ обычно работают с `REAL`, logic ФБ - с `BOOL`.

Принудительная запись вида `Тип_данных#Значение` в текущей версии убрана. Тип ANY-порта меняется через свойства блока.

`ANY_BIT` не принимает `REAL`; при смешении типов соединений у `ANY`-портов проверяй фактический выбранный тип в свойствах.

## Изменение количества портов ФБ

Для изменения количества входов/выходов копируют существующий ФБ из основной библиотеки в `User Library`, переименовывают его и редактируют интерфейс.

Правило имени из документа: `<имя_блока>_N_K`, где `N` - количество входов, `K` - количество выходов. Пример: `ADD_5` для ADD с 5 входами. Для Modbus/OPC UA blocks используется тот же общий подход.

При редактировании интерфейса пользовательского варианта добавляют входы/выходы зеленым плюсом на вкладке данных/интерфейса и, когда требуется event execution, связывают новые переменные с event input `REQ`.

## Связи

Связи создаются:

- протягиванием линии между совместимыми портами;
- через контекстное меню `Создать соединение`;
- через `Ctrl+C` на исходном порте и `Ctrl+V` на входном порте.

Диалог соединения предлагает только совместимые порты. Если параметров нет, связь невозможна.

Связи между контурами могут быть data или event. В ссылочном отображении имена имеют формат:

- outgoing loop: `БЛОК.ПАРАМЕТР`;
- incoming loop: `ПРИЛОЖЕНИЕ.КОНТУР.БЛОК.ПАРАМЕТР`.

Можно преобразовать line connection в ссылку и назначить connection alias. При переименовании block/loop/application source names обновляются в connection references.

Важно: `connection alias` в Studio UI - это проектно-визуальная ссылка/псевдоним. Это не то же самое, что XML `Alias` в VCont runtime для привязки порта ФБ к Modbus-регистру.

## Порядок выполнения

Порядок ФБ в loop определяется:

- неявно по мере добавления блока в контур;
- явно через значение порядка в свойствах каждого блока;
- явно через команду `Рассчитать порядок`.

Для runtime/bootfile это значит: порядок `CREATE FB` и команды изменения порядка являются частью поведения. Не сортируй blocks ради читаемости, если это может поменять исполнение.

## Event Loop Guardrails

Для event task нужно генерировать event и передавать его по event connection.

Типовой старт:

- `E_RESTART`, переименованный в `START`, генерирует одно событие на `COLD` после включения;
- `E_CYCLE` генерирует циклические события при событии START;
- period задается в `DT`, например `1000 ms`;
- чтобы все ФБ были последовательно обработаны, event-входы ФБ соединяют цепочкой.

Избегай:

- event branching: порядок выполнения становится неопределенным;
- event cycle/closure: блоки могут обрабатываться без паузы и загрузить resource на 100%.
