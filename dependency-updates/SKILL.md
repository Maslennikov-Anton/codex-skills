# Обновление зависимостей

Статус: `experimental`. Результат — проверенное обновление выбранных пакетов либо доказанный blocker совместимости. Анализ без запроса на обновление не разрешает менять manifest, lockfile, окружение или создавать внешние задачи.

1. Зафиксируй target и scope: пакеты, допустимые версии, runtime/OS, менеджер, manifest/lockfile и текущее окружение. Различай установленную и объявленную версию, прямые и транзитивные зависимости. Используй существующий менеджер проекта.
2. Прочитай официальный changelog/upgrade guide от текущей версии до кандидата. Найди вызовы и конфиги, которых касаются изменения. Проверь `Requires-Python`, платформу, плагины, ABI и изменения defaults; patch/minor сами по себе не гарантируют совместимость.
3. Построй порядок по реальным ограничениям. Пакеты с пересекающимися ограничениями обновляй совместно или в доказанном порядке; правило «всегда сначала leaf/runtime» без анализа constraints не применять. Runtime/OS/DB migration — отдельная граница scope.
4. Для Python/uv прочитай [references/python-updates.md](references/python-updates.md). Разреши точные кандидаты в отдельной копии/venv, проверь diff полного resolved graph и импорт нужных плагинов. Если установка не состоялась, не объявляй обновление проверенным.
5. Выполни релевантные tests/smoke до и после. Для breaking change проверь измененный контракт и прежние supported случаи. Существующие продуктовые красные тесты сохрани; сравни baseline, полноту запуска и результат обновления отдельно. Пройди обязательные repo gates; дорогой полный suite запускай, когда он нужен для заявляемого результата.
6. Если обновление разрешено и проверено, внеси только нужные manifest/lockfile/code изменения. Отчет включает old→new, транзитивный diff, проверки и оставшиеся ограничения. Commit, push, merge, публикация и production deploy не подразумеваются обновлением пакета.

Не включай автоматическое `--fix`, широкое обновление всех пакетов или изменение системного Python в узкую задачу. Недоступный changelog/registry — unknown, а не признак совместимости.

Источники и лицензия: [references/upstream.md](references/upstream.md). Для уязвимостей и состояния upstream используй dependency audit в `security-engineer`; для обычной Python-разработки — `python-developer`.
