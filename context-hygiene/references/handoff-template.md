# Handoff Template

## Compact State Snapshot

Используй этот формат для продолжения работы после длинной сессии:

```markdown
Цель:
- ...

Текущий статус:
- ...

Сделано:
- ...

Решения:
- [confirmed] ...
- [suspected] ...
- [rejected] ...

Измененные файлы:
- path: что изменено

Проверки:
- команда: результат

Failing evidence:
- команда/симптом: ключевые строки output или observed факт

Открытые вопросы:
- ...

Следующий шаг:
- exact command или файл + действие
```

## Что включать

- Только детали, которые изменяют дальнейшие действия.
- Абсолютные или repo-relative пути к файлам.
- Конкретные команды в исполняемом виде.
- Следующую команду, которую должен выполнить продолжающий агент.
- Ошибки и результаты проверок в сжатой форме.
- Причины решений, если без них следующий агент может повторить неверный путь.

## Что исключать

- Полные логи, если важны только 2-3 строки.
- Повторные формулировки одной и той же цели.
- Черновые планы, которые уже заменены текущим планом.
- Секреты, credentials, tokens и приватные URL.
- Длинные цитаты из внешних источников.

## Resume после compaction

При продолжении после compaction:

1. Прими summary как отправную точку, но не как безусловную истину.
2. Проверь ближайший блокирующий факт локально, если он дешевый: `git status`, наличие файла, результат последней команды.
3. Продолжай с next action, а не с повторного исследования всего проекта.
4. Если summary противоречит текущему состоянию файлов, доверяй файлам и командам.
