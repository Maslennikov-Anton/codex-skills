# Context Hygiene

Используй этот skill, когда сессия стала длинной, нужно продолжить работу после compaction/resume, подготовить handoff, сохранить важные решения или убрать лишний контекст перед новой фазой задачи.

## Workflow

1. Отдели устойчивый контекст от шума:
   - цель пользователя;
   - текущий статус;
   - принятые решения;
   - измененные файлы;
   - проверенные гипотезы;
   - команды и результаты, которые реально влияют на дальнейшую работу.
2. Удали из рабочей памяти:
   - длинные логи без новых сигналов;
   - промежуточные рассуждения, которые уже отменены фактами;
   - повторяющиеся планы;
   - детали источников, если достаточно ссылки или локального пути.
3. Сформируй компактный state snapshot.
4. Если задача продолжается в коде, добавь next action с конкретной командой или файлом.
5. Если знание должно пережить текущую сессию, используй подходящий persistent memory или локальный reference-файл.

## Что покрывает этот skill

- Handoff между длинными этапами работы.
- Восстановление после автоматического compaction.
- Краткие summaries для пользователя без потери actionable деталей.
- Подготовку durable notes для повторяющихся проектных знаний.
- Снижение токенового шума в больших расследованиях.

## Базовые правила

- Не сохраняй секреты, tokens, cookies, приватные ключи и персональные данные.
- Не превращай summary в полную историю чата.
- Не сохраняй гипотезу как факт: помечай статус `confirmed`, `suspected`, `rejected`.
- Handoff для кода должен содержать exact next command, changed files, commands already run, failing evidence и ближайший blocker.
- Для знаний, которые должны стать частью файловой PARA-памяти, дополнительно используй `para-memory-files`.
- Для правил команды и эволюции skills дополнительно используй `team-engineering-style`.

## Формат ответа

Когда просят summary или handoff, возвращай:

1. Цель и текущий статус.
2. Что уже сделано.
3. Ключевые решения и evidence.
4. Измененные файлы или внешние артефакты.
5. Открытые вопросы и риски.
6. Следующий конкретный шаг.
