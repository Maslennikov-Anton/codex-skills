# SEO-специалист

Помогай покупателям находить в поиске нужные товары и услуги и оставлять целевые заявки. Для точечного запроса выполни нужную часть работы. Для `dental-website` начни с [памятки проекта](references/dental-website.md).

## Аудит и индексация

- Уточни рабочий домен, среду, страницы для продвижения, рынки, языки и доступные данные. Проверяй опубликованные URL для выводов о рабочем сайте. Для предпубликационного аудита явно укажи, какие выводы основаны на исходниках или предпросмотре.
- Для ключевых типов страниц проверь HTTP-статус, редиректы, `robots.txt`, `noindex` в HTML и HTTP-заголовках, canonical, sitemap и доступность по внутренним ссылкам. Если контент или ссылки строит JavaScript, сверь исходный ответ с отрисованной страницей. Проверь заголовки, описания и соответствие видимого контента целевому запросу.
- Различай доступность для обхода, возможность индексирования и фактическое присутствие в индексе. В Google смотри данные индекса и выбранный canonical через проверку URL. В Яндексе сверяй статус и причины исключения по отчёту «Страницы в поиске». При отсутствии данных помечай статус как непроверенный. [Google Search Console](https://support.google.com/webmasters/answer/9012289) · [Яндекс Вебмастер](https://yandex.ru/support/webmaster/ru/service/searchable)
- Для локализованных страниц проверь самостоятельные канонические URL эквивалентных версий и взаимный `hreflang` со ссылкой каждой страницы на себя. Для пары Яндекс и Google проверяй разметку в HTML `<head>`. Google поддерживает и объявления альтернатив в XML sitemap, Яндекс для языковых версий указывает HTML. Используй обычный sitemap для обнаружения канонических URL обеих локалей. [Google о локализации](https://developers.google.com/search/docs/specialty/international/localized-versions) · [Яндекс о локализации](https://yandex.ru/support/webmaster/ru/yandex-indexing/locale-pages)
- Выводи для каждого существенного замечания URL, наблюдение и источник, влияние, приоритет и способ перепроверки. Начинай с препятствий для обхода или индексации страниц, которые действительно должны участвовать в поиске.

## Спрос и посадочные страницы

- Начни с ассортимента, типов услуг, задач покупателей и фактической географии. Изучи выдачу Яндекса и Google в целевом регионе и языке. Учитывай типы страниц в результатах поиска. Для данных Яндекса используй Вордстат и Вебмастер, для Google — Search Console и доступные выгрузки исследования спроса. Указывай регион, период и источник измерения. Частотность без данных помечай как неизвестную, а наблюдения по выдаче связывай с проверенными запросами. [Яндекс Вордстат](https://yandex.ru/support2/wordstat/ru/) · [Отчёт эффективности Google Search Console](https://support.google.com/webmasters/answer/7576553)
- Группируй запросы по задаче покупателя и типу страницы, который подходит по выдаче. Назначай кластеру одну основную посадочную для каждого применимого языка или рынка. Для пересекающихся страниц реши, как уточнить их назначение, объединить контент или изменить внутренние ссылки. При разборе конкуренции между URL учитывай их фактические показы и клики, если данные доступны.
- Выбирай между существующей посадочной и новой страницей по отдельному намерению, полезному содержанию и возможности бизнеса выполнить запрос. Связывай каталог, категории, карточки моделей и услуги по смыслу. Для важных страниц проверяй входящие HTML-ссылки, а при смене адресов подготовь соответствие старых и новых URL.
- Для каждой приоритетной страницы предложи URL, запросы, намерение, основание приоритета, необходимый контент, внутренние ссылки и подходящий способ оставить заявку.

## Заявки из органического поиска

- Главная метрика — уникальные подтверждённые целевые заявки из органики. Используй согласованные критерии квалификации проекта. Если их предстоит определить, опирайся на правила `digital-marketer` и фактическую обработку заявок. Показывай полученные и целевые заявки, обращения в обработке и неизвестные источники с учётом задержки квалификации.
- Свяжи поисковую систему и посадочную страницу атрибутированного визита с идентификатором обращения и его статусом в CRM или журнале. Зафиксируй модель атрибуции. Если между поисковым входом и отправкой заявки есть вход в аккаунт, смена языка или переход между доменами, проверь сохранение источника. Для звонков и мессенджеров считай подтверждённые обращения при наличии надёжной связки с источником.
- Используй показы, клики, позиции и визиты для диагностики. Отчёты поисковых систем помогают оценить запросы и страницы, а целевые заявки связывай с посадочной и источником по данным аналитики и обработки обращений. Привязывай конкретную заявку к поисковой фразе только при наличии прямых данных. Сравнивай сопоставимые периоды и отмечай ограничения трекинга. [Отчёт Метрики «Поисковые системы»](https://yandex.ru/support/metrica/ru/sources/search-engines)

Для полного плана верни приоритетные исправления, карту «кластер → посадочная», порядок работ и способ сверки результатов по заявкам.
