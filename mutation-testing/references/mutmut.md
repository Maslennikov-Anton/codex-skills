# mutmut: локальный ограниченный прогон

Проверяемая линия: `mutmut 3.8.0`, Python 3.12, Linux с `fork`. Версию узнай через package metadata интерпретатора, которому принадлежит CLI. У 3.8.0 даже `--help` загружает конфиг и может упасть в произвольном cwd без source paths; сначала создай конфиг в отдельной копии. Доступные команды и флаги проверь там через `--help`.

На этой машине CLI — постоянный `uv tool`, отдельно от helper/project venv. Для проекта нужны его зависимости в окружении mutation tool либо run-owned venv с той же версией mutmut и зависимостями проекта. Не меняй менеджер/lockfile проекта ради пилота.

Минимальный `pyproject.toml` в отдельной копии:

```toml
[tool.mutmut]
source_paths = ["src/"]
pytest_add_cli_args_test_selection = ["tests/"]
pytest_add_cli_args = ["-x", "-q"]
```

```bash
mutmut run --help
mutmut run --max-children 1
mutmut results --all true
mutmut show 'package.module.x_function__mutmut_1'
```

ID возьми из фактического `results`. По умолчанию команда показывает только survivors: пустой stdout не означает отсутствие мутаций. Сохрани также `--all true` и сводку campaign. Для выборочного прогона используй поддержанный этой версией wildcard. `browse` — необязательный TUI; evidence сохраняй командами, которые завершаются без интерактива. Старые примеры `paths_to_mutate` не переносить без проверки версии; актуальная документация использует `source_paths`.

`mutants/` содержит состояние и копии. Кэш разных исходников/конфигов/тестов нельзя выдавать за сопоставимый прогон: сохрани старый каталог и начни новую копию для строгого before/after. При incremental rerun проверь, что выбранные мутации реально пересчитаны.

Фильтры `max_stack_depth`, `do_not_mutate`, `mutate_only_covered_lines` меняют область измерения — укажи их в отчете. Equivalent означает одинаковое поведение на всем допустимом контрактом домене; одного примера для этого мало.

Проверь исходный набор после кампании явным `python -m pytest tests/`: общий discovery из root может захватить `mutants/tests` и дать import mismatch. Это ошибка scope запуска, не продуктовый дефект. Код возврата CLI и ненулевой kill rate не заменяют разбор timeout/error/незавершенных результатов. Cosmic Ray — альтернативный движок при отдельной необходимости распределенных сессий; второй инструмент не обязателен.
