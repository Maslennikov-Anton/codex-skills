# Поиск и triage

## От конкретного места к семейству

Сначала проверь фактический код известного дефекта и выпиши точный фрагмент. Например, если доказана потеря проверки статуса HTTP-ответа:

```bash
rg -n -F 'payload = response.json()' src
rg -n '\.json\(' src scripts
```

Второй запрос намеренно шире: читай обработку ответа, wrapper и callers. Отсутствие `raise_for_status()` в том же блоке само по себе не доказывает дефект: статус может проверяться выше или обработка ошибок может быть частью контракта.

Если текстовый поиск не различает контекст, используй AST для вызовов/условий или доступный анализатор потоков данных. Запрос должен находить исходную проблему и иметь безопасный контрольный пример. Не выдавай неподтвержденный CodeQL/Semgrep шаблон за рабочее CI-правило.

## Оси обобщения

- Другое имя helper/поля при том же нарушении контракта.
- Другой consumer того же helper: API, CLI, CI, report generator.
- Другой тип/граница входа: пустой список, `None`, ноль, Unicode — только если соответствующий контракт это допускает.
- Аналогичная операция с другим представлением данных или исключением.

Ищи в согласованном коде, включая sibling modules; generated/vendor/архивы не смешивай с исполняемым source. Не исключай tests автоматически: они помогают понять контракт, но совпадение в специально дефектном fixture не является багом продукта.

## Статусы кандидатов

| Статус | Достаточное основание |
|---|---|
| Confirmed | Нарушение контракта доказано воспроизведением или полным локальным путем данных/управления |
| Suspected | Похожая причина вероятна, но не доказана достижимость, домен или поведение зависимости |
| False positive | Есть конкретная защита, другой контракт или намеренно дефектный fixture |

Поведение внешней зависимости сверяй с текущей версией/официальным источником, если вывод зависит от него. По возможности проверяй known-bad и safe control одной проверкой. Сохраняй честный статус, если воспроизведение невозможно.

## Краткий отчет

```markdown
Исходный дефект: контракт, место, root cause, пример.
Область: дерево/ревизия, исключения и бюджет.
Поиск: команды, какие обобщения добавили кандидатов.

| Место | Статус | Evidence / защита | Следующее действие |
|---|---|---|---|

Ограничения: недоступные пути/зависимости, непроверенные направления.
```

Указывай severity по воздействию и достижимости, когда она нужна для triage. Один root cause может давать разные последствия; не копируй severity исходного дефекта всем совпадениям.
