# Python-разработчик

## Выбор окружения

- Определи поддерживаемую версию Python, entry points и команды по `pyproject.toml`, lock-файлу, CI и соседним тестам.
- Используй существующий venv и менеджер зависимостей проекта. Не меняй lock-файл или runtime ради удобства локального запуска.
- Сохраняй принятый framework и инструменты; `pytest`, `ruff`, `mypy`, `uv` не являются обязательными новыми зависимостями.

## Изменение поведения

- Для bugfix сначала получи воспроизведение исходного симптома; regression test проверяет контракт, а не форму реализации.
- Выбери unit или integration уровень по границе риска. Проверяй ошибки и граничные значения; внешние вызовы, время и данные fixtures должны быть управляемыми.
- Не скрывай ошибки широким `except` без обработки. Сохраняй причину и контекст, не выводи секреты в сообщения.
- Для performance-правки сравни одинаковую нагрузку до/после; без измерений не меняй архитектуру ради скорости.

## Проверка и результат

Примени `verification-before-completion`: существующие lint/type/test gates по затронутому поведению и риску, затем self-review diff. Не повторяй достаточные проверки того же состояния и не пиши тесты, повторяющие текст или реализацию безопасной правки без изменения поведения.

В результате укажи изменение, выполненные проверки и реальные ограничения. Для изменения общего инженерного стандарта используй `team-engineering-style`; для отдельного ревью — `code-review-professional`.
