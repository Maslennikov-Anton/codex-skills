# Пробелы в тестах

Экспериментальный метод для review выбранного поведения; адаптирован из GitHub Awesome Copilot. Источник и лицензия: [upstream.md](upstream.md).

1. Зафиксируй public behavior и changed surface. Различай глубоко проверенные файлы и только surveyed scope; read-only запрос не разрешает дописывать тесты.
2. Проследи вызывающие tests, fixtures и helpers до assertion. Unit тест helper может быть лишним, если надежный integration test уже проверяет его контракт; test count и line coverage этого не решают.
3. Для существенного условия выбери вход, при котором ожидаемый результат отличается от правдоподобной ошибки. Проверь, заметит ли существующий oracle эту разницу. Это помогает обнаружить assertion, который проверяет только «не упало» или mock call.
4. Предлагай gap только с конкретным input/precondition, public expected outcome, доказательством существующего покрытия/его недостатка и минимальным надежным test level. Поиск без совпадений ограничивай реально просмотренной областью.

Различай confirmed gap, suspected gap и отсутствующий контракт. Не повышай severity просто за отсутствие отдельного тест-файла. Для требования из документа используй `requirements-coverage-audit`, если нужна полная traceability.

Пример: тест обработки списка проверяет один уникальный ID. Mutant удаляет повторы через `set`, но тест остается зеленым. Нужен duplicate input и сравнение мультимножеств; сотня новых тестов без повторов gap не закроет.
