# Содержание README

## Выбор содержания

- Определи читателя и его первый полезный результат. Для внутреннего проекта, библиотеки и конфигурации нужны разные сведения.
- Начни с назначения в 1–2 предложениях и кратчайшего рабочего примера или запуска с необходимыми prerequisites.
- Добавляй основные команды, режимы и ограничения, которые нужны этому читателю. Проверяй команды по реальным entry points, конфигурации и принятому в проекте package manager.
- Подробные требования, архитектуру, API, эксплуатационные процедуры и тестовые матрицы размещай в соответствующих документах; из README давай ссылки на существующие материалы.
- Существенные ограничения и известные дефекты, влияющие на использование, обозначай рядом с соответствующим примером или командой; подробности давай по ссылке.
- Отчёты прогонов, историю отладки и журнал работы агента сохраняй отдельно. Включай их в README только по явному запросу или если это установленное назначение документа.

## Тестовые и QA-проекты

README должен помогать запустить проверки и понять границы результата. Укажи локальный запуск и необходимые режимы; CI jobs, quality gates, область покрытия и known bugs опиши кратко либо дай точные ссылки на соответствующие документы. Детальные матрицы и отчёты не дублируй. Не представляй наличие тестов как доказательство полного покрытия или отсутствия дефектов.

## Редактура

- При добавлении команды или исправлении факта сохрани структуру и стиль документа. Расширяй объём правки только для устранения связанной ошибки.
- Удаляй повторы, общие обещания и вводные, которые не помогают выполнить действие или понять ограничение. Сохраняй необходимые предупреждения, условия и шаги.
- Выбирай абзац, список или таблицу по содержанию; не выделяй каждый пункт жирным и не добавляй декоративные разделы.
- Не вводи общий лимит строк: сложность проекта и явно запрошенная глубина могут требовать подробного README. Проверь, что каждый раздел помогает конкретной задаче читателя.

## Источники подхода

Адаптированы принципы выбора аудитории и содержания из [crafting-effective-readmes](https://github.com/softaworks/agent-toolkit/blob/main/skills/crafting-effective-readmes/SKILL.md) и краткого, конкретного письма из [writing-clearly-and-concisely](https://github.com/softaworks/agent-toolkit/blob/main/skills/writing-clearly-and-concisely/SKILL.md). Они не требуются как установленные skills; для применения этих правил достаточно локальных инструкций.
